Từ khi nhận một task mới đến lúc kiểm tra, tích hợp và merge code.

Workspace Manager giúp mỗi agent làm việc trong source riêng, chạy môi trường test riêng khi cần, sau đó tích hợp và kiểm tra trước khi đưa code vào main.

Ba giới hạn an toàn: Không sửa main trực tiếp · Không xoá worktree có thay đổi chưa commit · READY_FOR_MAIN vẫn phải qua GitHub PR + CI.

BẮT ĐẦU NHANH

Bắt đầu nhanh

Toàn bộ vòng đời một task, từ lúc tạo tới lúc sandbox được dọn dẹp:

  1. Tạo TaskMột công việc mới cho bug hoặc feature.
  2. Thêm Agent WorkspaceChọn repository, agent, role và sandbox cho từng phần việc.
  3. Mở Claude / CodexBấm Open Claude / Open Codex, terminal mở đúng worktree của task.
  4. Agent sửa code + testLàm việc trong source riêng, không đụng main hay agent khác.
  5. Mark ReadyBáo workspace đã sẵn sàng để tích hợp.
  6. Create IntegrationGhép các Agent Workspace đã Ready lại để kiểm tra chung.
  7. Integration Agent merge + testXem diff, merge, chạy test, kiểm tra sandbox.
  8. READY_FOR_MAINĐủ điều kiện để mở Pull Request.
  9. PR / CI / MergeTạo GitHub Pull Request, chờ CI PASS, merge trên GitHub.
  10. Sandbox tự cleanupSau thời gian giữ lại (mặc định 24 giờ).

AGENT WORKSPACE

Agent Workspace là gì?

Mỗi Agent Workspace là một vùng source riêng cho một agent. Claude sửa task A sẽ không sửa trực tiếp vào source đang dùng bởi Codex hoặc main.

Claude
→ branch riêng
→ worktree riêng
Codex
→ branch riêng
→ worktree riêng
MỘT AGENT WORKSPACE = MỘT REPOSITORY + MỘT BRANCH + MỘT WORKTREE

Bạn không cần tự cd tới thư mục worktree. Bấm Open Claude / Open Codex để Workspace Manager mở đúng nơi (xem mục kế tiếp).

DESKTOP LAUNCHER

Bắt đầu cho agent sửa code

Trong Agent Workspace có các nút:

Open Claude / Open CodexMở terminal ngay tại worktree của task, chạy sẵn agent CLI.
Open TerminalChỉ mở terminal tại đúng worktree, không tự chạy agent.
Copy PathSao chép đường dẫn worktree nếu bạn muốn tự mở bằng công cụ khác.

Ví dụ

Nếu workspace thuộc Claude: bấm Open Claude. Terminal sẽ mở ngay tại đúng worktree của task.

Không nên mở Claude/Codex ở source main/shared rồi yêu cầu sửa cùng task.
Cảnh báo mức quyền cao

Claude có thể được mở bằng claude --dangerously-skip-permissions. Codex có thể được mở bằng codex --yolo. Các mode này cho agent quyền thao tác mạnh trong worktree. Chỉ dùng vì source của task đã được cô lập — không dùng các mode này trên main hoặc source dùng chung.

SANDBOX

Sandbox dùng để làm gì?

Worktree= cô lập source code
Sandbox= cô lập ứng dụng đang chạy
Claude Worktree A
→ Sandbox A
Codex Worktree B
→ Sandbox B

Nếu hai agent cùng chạy backend/database trên một môi trường chung, test có thể đạp dữ liệu hoặc port của nhau. Sandbox tạo môi trường test riêng cho từng task — mỗi sandbox có port và database riêng.

CHỌN SANDBOX

Chọn Sandbox thế nào?

AutoKhuyên dùng. Workspace Manager chọn profile theo cấu hình của project.
NoneKhông tạo môi trường runtime. Dùng cho docs, code analysis, thay đổi không cần chạy app.
BackendTạo backend + database cần thiết cho task.
Full StackTạo môi trường đầy đủ: backend, frontend, QA hoặc service phụ.
Hardware / KioskDùng khi ESP/Kiosk cần kết nối tới backend sandbox qua LAN.
Shared DevDùng môi trường development dùng chung, không hoàn toàn isolated. Chỉ dùng khi biết rõ task không ảnh hưởng môi trường khác.
Nếu không chắc, chọn Auto.

INTEGRATION AGENT

Integration Agent làm gì?

Integration Agent không phải agent viết feature chính. Nó chịu trách nhiệm:

  • Xem diff của các branch
  • Kiểm tra source nào thay đổi
  • Merge
  • Phát hiện conflict
  • Xử lý conflict đơn giản
  • Chạy test
  • Kiểm tra sandbox
  • Báo READY_FOR_MAIN hay FIX_REQUIRED

Bấm Open Integrator để mở Claude/Codex tại môi trường Integration.

CONFLICT

Nếu merge bị conflict

  • Conflict đơn giản: Integration Agent có thể tự xử lý.
  • Conflict logic/API/schema: Integration Agent phải phân tích trước khi sửa.
  • Nếu không chắc: status = FIX_REQUIRED và trả việc về Agent Workspace phù hợp.
Không cần sửa lỗi của Claude trên integration branch nếu lỗi đó thực sự thuộc branch Claude. Quay lại Claude Workspace → sửa → commit mới → Merge Latest.

CẢNH BÁO

SOURCE STALE nghĩa là gì?

Sandbox đã được tạo từ commit cũ, nhưng branch đã có commit mới.

Ví dụ

Sandbox: abc123 · Current: abc999

Hành động: bấm Rebuild Sandbox.

Kết quả test cũ không còn đủ để xác nhận code mới.
SO SÁNH

Restart hay Rebuild?

RestartChạy lại cùng sandbox/source hiện có.

Dùng khi: service treo, backend cần restart.
RebuildBuild lại sandbox từ source hiện tại (commit mới nhất).

Dùng khi: agent vừa commit code mới, Docker image cần build lại, source đang SOURCE STALE.
TRA CỨU

Trạng thái Sandbox

Trạng tháiÝ nghĩa
RUNNINGSandbox đang chạy và health check PASS.
UNHEALTHYContainer có thể đang chạy nhưng ứng dụng chưa healthy.
STOPPEDSandbox đã dừng nhưng data vẫn còn.
FAILEDProvision/start/rebuild gặp lỗi.
SOURCE STALESource đã thay đổi từ lần sandbox được build/test.
CLEANUP ELIGIBLETask đã merge/cancel và sandbox đang chờ cleanup.
CLOSEDRuntime sandbox đã được dọn. Metadata/test evidence vẫn còn.

READINESS

READY_FOR_MAIN nghĩa là gì?

Task đã qua các bước kiểm tra cần thiết và có thể đưa sang PR/CI.

  • Các source branch đã merge vào Integration
  • Không còn conflict
  • Integration sandbox healthy
  • Required tests PASS
  • Source chưa thay đổi sau lần test
  • Verified commit đúng với HEAD hiện tại
Với task nhiều repo: tất cả repository tham gia phải đạt trạng thái tương ứng.
READY_FOR_MAIN không có nghĩa là đã merge main.

Nó chỉ có nghĩa integration đã đủ điều kiện để tạo Pull Request.

BƯỚC CUỐI

Sau READY_FOR_MAIN

Push integration branch→Tạo GitHub Pull Request→GitHub CI→CI PASS→Merge main
git push -u origin integration/session-management
Workspace Manager không bypass GitHub CI và không tự merge main. Tạo Pull Request và merge trên GitHub là thao tác thủ công ngoài Workspace Manager — hiện tại phiên bản này chưa tự động tạo PR hay tự merge.
Tiếp theo: Push branch và tạo Pull Request.
SAU MERGE

Sau khi task merge thành công

Sandbox không bị xóa ngay.

MERGED
↓ Retention
↓ mặc định 24 giờ
↓ Auto Cleanup

Giữ lại một thời gian để còn xem logs, runtime, DB sandbox, evidence — nếu vừa merge xong mà phát hiện vấn đề.

Cleanup xoá: containers, sandbox network, sandbox volumes, generated runtime env, port reservations.

Cleanup giữ lại: task history, source commits, test results, audit, integration report.

Nút điều khiển cleanup

Extend 24hDời thời điểm cleanup thêm 24 giờ.
Cleanup NowDọn ngay lập tức. Chỉ xoá runtime/data của sandbox, không xoá source code.
Huỷ lịch cleanupBấm Start trên sandbox đang Cleanup Pending — sandbox chạy lại và tự động ra khỏi hàng chờ cleanup.
SO SÁNH

Stop khác Cleanup thế nào?

StopDừng ứng dụng · giữ data · giữ port · có thể Start lại.
CleanupXóa runtime sandbox · xóa sandbox-owned data/volume · release port · metadata/evidence vẫn còn.
REPOSITORIES

Repositories

Workspace Manager không cần nằm trong repository được quản lý — repo có thể ở bất kỳ đâu dưới workspace root đã cấu hình.

Configured root{{settings.root}}

Vào Repositories để Register repo mới, hoặc chọn từ danh sách Discovered. Danh sách Discovered luôn tự làm mới mỗi khi bạn mở lại trang — nếu vừa thêm hoặc di chuyển một repo, chỉ cần tải lại trang Repositories.

KHÔNG CÓ SANDBOX

Project không khai báo Sandbox

Nếu Task Detail hiện dòng:

Sandbox is not configured for this repository.

Agent vẫn có thể làm việc bình thường bằng worktree — Sandbox chỉ là tính năng tuỳ chọn. Muốn có sandbox tự động, project cần khai báo sandbox: trong PROJECT.yaml của repository đó (phần kỹ thuật này do người phụ trách repo cấu hình, không bắt buộc với mọi project).

KHI CÓ LỖI

Khi test fail

Nếu lỗi thuộc một Agent Workspace: quay lại workspace đó → Open Claude/Codex → sửa → commit → Mark Ready → Integration Merge Latest → retest.

Nếu là conflict chỉ phát sinh khi tích hợp (không thuộc riêng branch nào): Integration Agent có thể tạo integration-only fix.

Nếu sandbox fail

  1. Xem Status
  2. Mở Logs
  3. Xem Health
  4. Retry / RebuildBấm Start để thử lại, hoặc Rebuild nếu source đã đổi.
Sandbox fail không đồng nghĩa source worktree bị mất — code của agent vẫn còn nguyên, chỉ môi trường chạy thử bị lỗi.

Nếu hết chỗ chạy sandbox

SANDBOX_CAPACITY_FULL

Lựa chọn: Stop sandbox không dùng, Cleanup sandbox cũ, hoặc tạo workspace không có sandbox (profile None). Workspace Manager không tự kill sandbox khác của bạn.

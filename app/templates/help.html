TỔNG QUAN

Workspace Manager dùng để làm gì?

Mỗi agent làm việc trong 1 branch riêng + 1 Git worktree riêng + 1 source folder riêng. Codex và Claude không dùng chung checkout, nên có thể code và test độc lập mà không ghi đè working tree của nhau.

CODING

Codex

agent/codex/session-filter.worktrees/codex-session-filter
READY

Claude

agent/claude/session-review.worktrees/claude-session-review
main
├── Codex workspace
├── Claude workspace
└── Integration workspace
↓ Tests ↓ READY_FOR_MAIN ↓ GitHub PR ↓ CI ↓ main
12 BƯỚC

Bắt đầu nhanh

  1. Đăng ký RepositoryChỉ cấp quyền quản lý cho repo bạn chọn.
  2. Tạo Agent WorkspaceChọn agent, task và base branch.
  3. Cho agent code trong folder được cấpKhông dùng canonical checkout.
  4. Mark ReadyKhi branch agent đã commit và sẵn sàng.
  5. Tạo IntegrationChọn các agent branch cần test chung.
  6. Merge các agent branchApp merge vào integration, không merge main.
  7. Run TestsChạy contract thật từ PROJECT.yaml.
  8. PASS → READY_FOR_MAINChỉ cho đúng HEAD đã test.
  9. Push integration branchCopy lệnh push từ integration detail.
  10. Tạo GitHub Pull RequestTarget là main.
  11. Chờ CI PASS và reviewGitHub là gate cuối.
  12. Merge mainThực hiện ngoài Workspace Manager.
BƯỚC 1

Đăng ký Repository

Vào Repositories, chọn repo Workspace Manager được phép quản lý. Repo phải nằm dưới workspace root; app resolve absolute path và chặn arbitrary filesystem path. Đăng ký repo không sửa code.

Ví dụ

Repository: mesflow

/home/dell/workspace/mesflow/mesflow

Default branch: main

DESKTOP LAUNCHER

Mở agent trực tiếp

  1. Tạo Codex hoặc Claude WorkspaceWorkspace xác định owner, branch và source folder.
  2. Bấm Open Codex / Open ClaudeBrowser không gửi command hoặc path tùy ý.
  3. Terminal mở đúng folderLauncher kiểm tra Git worktree và desktop session trước.
  4. Agent chạy trong branch đã cấpCodex dùng --yolo; Claude dùng --dangerously-skip-permissions.
  5. Hoàn tất → Mark ReadyCommit thay đổi trước khi tích hợp.
Cảnh báo mức quyền cao

codex --yolo và claude --dangerously-skip-permissions chạy agent với mức permission cao. Chỉ dùng trong worktree riêng đã được Workspace Manager tạo.

Agent được quyền mạnh + source tree bị cô lập + main vẫn được bảo vệ. Terminal launcher chỉ hỗ trợ desktop session local. VPS, container không GUI hoặc remote server sẽ báo unsupported, không fake success.

Khi source branch có commit mới

Codex sửa thêm commit↓Integration trở thành STALE↓Merge Latest↓Run Tests lại
READY_FOR_MAIN chỉ hợp lệ cho đúng commit đã được test.
BƯỚC 4

Chạy test

Workspace Manager không tự nghĩ command test riêng. Nó đọc PROJECT.yaml → ci.required của repository và chạy contract thật trong integration worktree.

preflightPASS
testRUNNING

Khi mọi required stage PASS tại cùng HEAD, integration có thể được đánh dấu READY_FOR_MAIN.

Khi test fail

TEST FAILED↓View Log↓Agent owner sửa branch↓Commit → Merge Latest → test lại
Không nên sửa lỗi thuộc Codex branch trực tiếp trong integration branch, trừ khi lỗi thực sự chỉ phát sinh do interaction giữa nhiều branch.
READINESS

Khi nào là READY_FOR_MAIN?

  • No merge conflict
  • Integration tree clean
  • All source branches merged at latest commit
  • Required tests PASS
  • verified_commit == current HEAD
READY_FOR_MAIN không có nghĩa là đã merge main.

Nó chỉ có nghĩa local integration đã đủ điều kiện để tạo Pull Request.

BƯỚC CUỐI

Đưa code lên main

READY_FOR_MAIN→Push integration→GitHub PR→Actions CI PASS→Review→main
git push -u origin integration/session-management
Workspace Manager không bypass GitHub CI và không tự merge main.

AN TOÀN

Quy tắc nên tuân theo

ONE AGENT · ONE BRANCH · ONE WORKTREE
  • Không code trực tiếp trên main
  • Không share cùng source folder cho nhiều agent
  • Không merge branch chưa commit vào integration
  • Source branch thay đổi → integration phải test lại
  • Không xoá worktree đang dirty
  • Không dùng reset --hard để giải quyết conflict
  • Main chỉ nhận code qua PR + CI

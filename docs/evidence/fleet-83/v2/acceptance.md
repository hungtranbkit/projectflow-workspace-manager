## STATUS_PROBE_TIMEOUT investigation

Actual Terminal MCP controller terminal_status_bounded shares a caller deadline across session resolution and node I/O. Its timeout can mean resolution consumed the slice, too little budget remains, or a node request exhausted that slice. compact_tools._bounded_read additionally returns this for an already-active same-target probe, a full32-reader pool, or a future missing its deadline. These are read-budget outcomes, not authentication/OS-denial evidence. Qualified node/session IDs avoid unnecessary fleet name scans. Unknown or timed-out execution retains its request key and never permits mutation resubmission.

During NEC audit, an accepted send_wait response initially showed a stale IDLE tail. No second mutation was sent; a later independent readback found the expected completion marker and shell prompt. The final exact instance was then checkpointed and closed through the supported confirm route. The latest own close receipt verifies `$8@1795578128` absent and tombstoned; no similarly named older sessions were touched.
